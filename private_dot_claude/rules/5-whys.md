# 設計判断の5 Whys（ドメイン理解用）

設計判断を1つ選んで、「Why?」を5回繰り返す。最後にビジネス価値を明記する。

## テンプレート

```
設計: [具体的な設計判断]
↓ Why? [技術的理由]
↓ Why? [システム的理由]
↓ Why? [ドメイン的理由]
↓ Why? [ユーザー/ビジネス的理由]
↓ Why? [根本的なビジネスモデル/制約]
→ ビジネス価値: [この設計が生み出す価値]
```

## 例

```
設計: SKUをキーにしている
↓ Why? 商品バリエーション（色・サイズ）を区別するため
↓ Why? 在庫管理を商品単位ではなくバリエーション単位で行うため
↓ Why? 「赤のMサイズだけ在庫切れ」を表現する必要があるため
↓ Why? 顧客は特定の色・サイズを注文するため
↓ Why? ビジネスモデルがアパレルECだから
→ ビジネス価値: 正確な在庫表示 = 機会損失防止 & 誤販売防止
```

## 使い方

1. 新しい設計を導入する時
2. 既存のコードを読んで「なぜこうなっているのか？」を理解する時
3. リファクタリング前に、既存設計の意図を確認する時
