# 10年後シナリオの観点（5つ）

この設計は10年後も耐えうるか？様々なシナリオで長期的な耐久性を検証する。

## チェックリスト

```
□ スケール
  データが1000倍になっても動くか？
  インデックスは適切に設定されているか？
  ページネーションは実装されているか？
  N+1問題は発生しないか？

□ 拡張
  新しい種類のX（商品タイプ、決済方法、通知チャネルなど）が
  追加されても壊れないか？
  if/switch文の羅列ではなく、拡張可能な抽象化になっているか？
  Open/Closed原則は守られているか？

□ 法規制
  法律が変わっても対応できるか？
  データ保存期間、削除権（GDPR等）は考慮されているか？
  監査ログは十分か？
  法的要件の変更に柔軟に対応できる設計か？

□ 他システム連携
  外部APIが変更/廃止されても代替可能か？
  依存する外部サービスは長期的に維持されるか？
  APIバージョニングは考慮されているか？
  フォールバック戦略はあるか？

□ 理解可能性
  この設計判断の理由を、10年後の人は理解できるか？
  コメントやドキュメントに「なぜ」が記録されているか？
  型システムや抽象化で意図が表現されているか？
  ADR（Architecture Decision Records）は必要か？
```

## 実践

- PR作成時に、AIに質問: 「この変更で10年後壊れるシナリオは？」
- 大きな設計判断をする時は、これら5観点で検証
- リファクタリング時に、既存の設計が10年耐えてきた理由を考察
